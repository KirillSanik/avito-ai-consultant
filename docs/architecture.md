# Техническое задание: Модуль детекции AI-генерации кода (Homework AI Detector)

## 1. Цель и описание задачи
Разработать асинхронный Python-модуль для анализа решений домашних заданий, размещенных в GitHub-репозиториях. Модуль принимает на вход текст критериев задания и ссылку на репозиторий с решением. Система локально клонирует репозиторий, извлекает полную историю коммитов и весь исходный код, после чего с помощью локальной LLM (через OpenAI-совместимый API) выдает структурированную оценку вероятности AI-генерации по системе «Светофор».

## 2. Технологический стек
- **Язык:** Python 3.10+
- **Управление зависимостями:** `uv` (с `pyproject.toml` и `uv.lock`)
- **Асинхронность и I/O:** `asyncio`, `aiofiles` (для асинхронного чтения файлов)
- **Валидация и схемы:** `pydantic` (v2.x)
- **LLM Клиент:** `openai` (AsyncOpenAI, совместимый с vLLM / Triton Inference Server)
- **Системные зависимости:** Установленный бинарный файл `git` в ОС.
- **Стиль кода:** Объектно-ориентированный, строгая типизация (type hints), модульная структура.

## 3. Архитектура системы
Модуль состоит из трех логических слоев:
1. **Слой сбора данных (Data Layer):** Отвечает за клонирование, извлечение метаданных и чтение кода. Разделен на 3 класса: `RepoCloner`, `GitMetadataExtractor`, `LocalCodeAggregator`.
2. **Слой оценки (Evaluation Layer):** Класс `LLMJudge`, инкапсулирующий работу с LLM.
3. **Слой оркестрации (Orchestration Layer):** Фасад `AIDetectionService`, управляющий жизненным циклом и параллельным выполнением задач.

## 4. Описание компонентов

### 4.1. Схема данных (Pydantic Models)
Строгий контракт для Structured Output.

```python
from pydantic import BaseModel, Field
from typing import Literal, List

class AIAssessmentResult(BaseModel):
    status: Literal["green", "yellow", "red"] = Field(
        description="Вердикт: 'green' (человек), 'yellow' (смешанный/подозрительный), 'red' (явный ИИ/копипаст)"
    )
    confidence: float = Field(
        ge=0.0, le=1.0, 
        description="Уверенность модели в вердикте от 0.0 до 1.0"
    )
    reasoning: str = Field(
        description="Подробное, аргументированное обоснование вердикта на русском языке"
    )
    ai_indicators: List[str] = Field(
        description="Список конкретных признаков, указывающих на генерацию ИИ"
    )
    human_indicators: List[str] = Field(
        description="Список признаков, указывающих на человеческую работу"
    )
```

### 4.2. `RepoCloner` (Управление репозиторием)
**Задача:** Безопасно скачать репозиторий во временную директорию и гарантировать её очистку.
**Логика реализации:**
- Использует `tempfile.TemporaryDirectory` (или его асинхронный аналог).
- Выполняет `git clone <url> <temp_dir>` через `asyncio.create_subprocess_exec`, чтобы не блокировать event loop.
- Реализует паттерн **асинхронного контекстного менеджера** (`async with`), чтобы гарантировать удаление временной папки после завершения анализа, даже при возникновении исключений.
- Поддерживает передачу токена для приватных репозиториев через переменные окружения.

### 4.3. `GitMetadataExtractor` (Сбор метаданных)
**Задача:** Извлечь историю коммитов и структуру файлов без использования GitHub API (чтобы избежать лимитов и пагинации).
**Логика реализации:**
- Выполняет асинхронный `git log` с форматированием вывода в JSON: 
  `git log --pretty=format:'{"hash":"%H","author":"%an","date":"%aI","message":"%s"}' --no-merges`
- Парсит поток строк в список Pydantic-моделей `CommitInfo`.
- Выполняет `git ls-files` для получения чистого списка файлов в репозитории (дерево файлов).

### 4.4. `LocalCodeAggregator` (Сбор исходного кода)
**Задача:** Прочитать **весь** исходный код репозитория целиком (без экономии токенов) и подготовить его для промпта.
**Логика реализации:**
- Использует `pathlib.Path.rglob()` для рекурсивного обхода.
- **Фильтрация:** 
  - Whitelist расширений: `.py`, `.go`, `.rs`, `.js`, `.ts`, `.java`, `.cpp`, `.md`.
  - Blacklist директорий: `.git`, `__pycache__`, `venv`, `node_modules`, `.idea`, `.vscode`.
- Использует `aiofiles` для **асинхронного чтения** содержимого.
- Применяет `asyncio.Semaphore` для ограничения количества одновременных чтений (защита от исчерпания файловых дескрипторов).
- Формирует итоговую строку, оборачивая каждый файл в четкие маркеры:
  ```text
  --- FILE: path/to/file.py ---
  [полное содержимое файла]
  --- END FILE ---
  ```

### 4.5. `LLMJudge` (Оценка с помощью LLM)
**Задача:** Выполнить запрос к локальной LLM и гарантированно получить валидированный Pydantic-объект.
**Логика реализации:**
- Формирует системный и пользовательский промпт (см. раздел 5).
- Использует `AsyncOpenAI` (с `base_url`, указывающим на локальный сервер).
- Вызывает метод `client.beta.chat.completions.parse()`, передавая `response_format=AIAssessmentResult`.
- Возвращает `response.choices[0].message.parsed`.
- Реализует механизм повторных попыток (`tenacity`) на случай ошибок парсинга или таймаутов.

### 4.6. `AIDetectionService` (Фасад / Оркестратор)
**Задача:** Единая точка входа, управляющая параллельным выполнением I/O операций.
**Логика реализации:**
```python
class AIDetectionService:
    def __init__(self, llm_client: AsyncOpenAI):
        self.cloner = RepoCloner()
        self.metadata_extractor = GitMetadataExtractor()
        self.code_aggregator = LocalCodeAggregator()
        self.judge = LLMJudge(llm_client)

    async def analyze(self, task_criteria: str, repo_url: str) -> AIAssessmentResult:
        # 1. Клонируем репозиторий (контекстный менеджер гарантирует очистку)
        async with self.cloner.clone(repo_url) as repo_path:
            
            # 2. Параллельно собираем метаданные и код для ускорения работы
            metadata_task = self.metadata_extractor.extract(repo_path)
            code_task = self.code_aggregator.aggregate(repo_path)
            
            metadata, full_code = await asyncio.gather(metadata_task, code_task)
            
        # 3. Передаем агрегированные данные в LLM Judge
        result = await self.judge.evaluate(task_criteria, metadata, full_code)
        
        return result
```

## 5. Логика промпта (System Prompt для LLM Judge)

**Системная инструкция:**
> Ты — старший инженер по код-ревью и эксперт по детекции AI-генерации в коде. Твоя задача — проанализировать предоставленный код и метаданные репозитория и вынести вердикт о вероятности его генерации ИИ.
> 
> **КРИТЕРИИ ВЕРДИКТА (СТРОГО СОБЛЮДАЙ):**
> - 🟢 **GREEN (Человек):** Постепенная история коммитов с осмысленными сообщениями. Наличие неидеальностей, специфичные для задачи имена переменных. Код решает именно поставленную задачу, учитывая её нюансы. Комментарии по делу.
> - 🟡 **YELLOW (Смешанный/Подозрительный):** Код качественный, но история коммитов подозрительна (например, 1-2 коммита с разницей в минуту). Присутствуют избыточные, "водянистые" комментарии в стиле ИИ ("Этот код делает...", "Создаем переменную"), но видна попытка ручной адаптации под специфичные критерии задачи.
> - 🔴 **RED (ИИ-слоп/Копипаст):** Один коммит ("initial commit"). Идеальная, но бездушная структура. Галлюцинации в комментариях. Код решает общую абстрактную задачу, игнорируя специфические ограничения из критериев. Наличие артефактов нейросетей в коде или коммитах (например, "Конечно, вот ваш код", "Sure, here is the solution").
> 
> Твой ответ должен быть строго в формате JSON, соответствующем предоставленной Pydantic-схеме. Не добавляй никакой текст вне JSON.

**Пользовательский запрос (User Prompt):**
> **1. КРИТЕРИИ ЗАДАНИЯ:**
> {task_criteria}
> 
> **2. МЕТАДАННЫЕ РЕПОЗИТОРИЯ:**
> - Структура файлов: {file_tree}
> - История коммитов: {commit_history_formatted}
> 
> **3. ПОЛНЫЙ ИСХОДНЫЙ КОД:**
> {full_code}

## 6. Ограничения и допущения
1. **Отказ от GitHub API:** Намеренно не используется GitHub REST/GraphQL API для сбора данных. Локальное клонирование через `git` CLI позволяет обойти лимиты запросов, избежать сложной пагинации и гарантированно получить полную историю коммитов и все файлы за минимальное количество сетевых обращений.
2. **Системная зависимость:** Для работы модуля в среде выполнения должен быть установлен CLI-клиент `git`.
3. **Локальная LLM:** Предполагается, что модель развернута локально (vLLM, Triton) и поддерживает OpenAI-compatible API и Structured Output. Экономия токенов не требуется, в модель передается полный код всех файлов.
4. **Парсинг PDF не требуется:** Модуль принимает `task_criteria` уже в виде текстовой строки.

# CONTEXT_PACK.md — Avito AI Reviewer

## 1. Проблема одной фразой + чья это работа: ситуация → хочу → чтобы

**Ситуация:**  
Ревьюеры и методисты Авито Образование тонут в ручной рутине: работы прилетают из GitHub / Stepik / Google Docs, критерии есть, но всё равно приходится открывать каждый PR/решение, сверять с критериями, писать фидбек, руками переносить баллы в Google Sheets, гонять дедлайны и ловить «иишность». Эксперты тратят 5–10 ч/нед на проверку, методисты — до 10 ч/нед на координацию. При росте потоков это масштабируется как боль.

**Хочу:**  
AI-помощник, который берёт на себя предварительное ревью по критериям, распределение нагрузки, детекцию генеративного AI (с уверенностью и основаниями) и кусок админки, но **финальное решение всегда за человеком**.

**Чтобы:**  
Сократить время ревьюера/методиста в 2–3 раза, убрать просрочки, сделать процесс прозрачным и масштабируемым на все курсы, не потеряв качество и ответственность.

**Чья это работа:**  
Команда хакатона (мы) — MVP + архитектура.  
Авито — финальный владелец, данные, критерии, ревьюеры, политики по AI.

## 2. Как это делают сейчас и что это стоит

### Текущий процесс (из кейса + QA)

1. **Подготовка** — методист/преподаватель публикует задание + критерии + дедлайн. Таблица в Google Sheets. Распределение студентов по ревьюерам (часто «закреплено» или по договорённости).
2. **Сдача** — студент: PR в GitHub (тех) / Stepik (нетех) / ссылка на Google Docs.
3. **Первичное ревью** — ревьюер вручную открывает, сверяет с критериями, пишет развёрнутый фидбек, ставит балл.
4. **Повторное ревью** (если есть) — сравнивает версии.
5. **Фиксация** — руками переносит балл + комментарий + ссылку в Google Sheets.
6. **Контроль** — методист вручную мониторит статусы, дедлайны, напоминает, разруливает просрочки.

**Боли (из QA):**
- Субъективность ревьюеров (критерии есть, но «жёсткость» разная).
- Нет эталонов — только критерии.
- Уведомления о дедлайнах — в основном руками методиста.
- AI-использование студентами **сейчас не проверяется системно**.
- Google Sheets — костыль, данные размазаны по 3–4 системам.
- При росте курсов (геометрическая прогрессия) ручной процесс начинает «скрипеть».

**Стоимость:**
- Ревьюер: 5–10 часов в неделю.
- Методист: до 10 часов в неделю на поддержку процесса.
- Риск: пропущенные дедлайны, неравномерная нагрузка, ошибки при переносе, delayed feedback студентам.
- Бизнес-эффект Авито: качество людей в найм + HR-бренд. Плохой feedback loop = хуже кандидаты.

## 3. Обязательные требования кейса vs наши предположения — две колонки

| Обязательные требования кейса | Наши предположения / гипотезы |
|-------------------------------|-------------------------------|
| a. Распределение ДЗ между ревьюерами с учётом объёма курса и нагрузки | Можно делать smart-assignment по текущей загрузке + skill-match (тех/нетех) + historical quality |
| b. Предварительное ревью по заданным критериям → результат + рекомендации для ревьюера | LLM + structured output (JSON) по рубрике. Человек всегда может override |
| c. Выявление признаков gen-AI + confidence + основания. Только рекомендация, не автоштраф | Комбо: perplexity/GPTZero-style + style fingerprints + «AI-tell» (длинные тире, шаблонные фразы, отсутствие ошибок) + human-in-loop |
| ≥3 дополнительные функции | Мы выбираем: 1) уведомления по дедлайнам, 2) перенос в Google Sheets / API, 3) аналитика прогресса + типичные ошибки |
| Один канал сдачи для MVP (GitHub / Stepik / Docs) | MVP — **GitHub** (технические курсы), потому что код + PR = богатый контекст. Stepik/Docs — roadmap |
| Финальное решение всегда за ревьюером | Hard constraint. AI никогда не ставит итоговый балл |
| Не передавать PII / внутренние материалы во внешние незащищённые LLM | Локальные/внутренние модели или self-hosted + anonymization layer |
| Масштабируемость на другие курсы | Архитектура: pluggable adapters (GitHub/Stepik/Docs) + course-config (критерии, рубрики, правила AI) |
| Измеримый эффект | Время ревьюера ↓, % просрочек ↓, consistency оценок ↑, NPS студентов/ревьюеров |

**Наш edge:**  
Специально под процесс Авито (мульти-платформа, критерии из задания, distribution, Sheets, human final say) + «иишность» как сигнал, а не приговор.

## 6. 5–7 гипотез (продуктовые + AI), одна помечена как самое рискованное предположение

1. **Предварительное ревью LLM по критериям сократит время ревьюера на 40–60%** (он только правит/подтверждает).
2. **Smart-распределение по нагрузке + skill-match уменьшит просрочки и «горелые» ревьюеры**.
3. **AI-detection с confidence + основаниями будет полезен как «второй взгляд»**, даже если accuracy не 100%.
4. **Уведомления + автоперенос в Sheets** снимут 30–50% рутины методиста.
5. **Аналитика типичных ошибок** даст методистам сигнал для улучшения материалов (closed-loop).
6. **Студенты будут лояльнее**, если feedback быстрее и структурированнее (вторичный эффект на HR-бренд).
7. **Самое рискованное:** «AI-detection можно сделать достаточно точным и actionable на текущих открытых моделях + эвристиках без доступа к внутренним данным Авито и без огромного labeled датасета».  
   (Риск: высокий false positive/negative → ревьюеры начнут игнорировать сигнал.)

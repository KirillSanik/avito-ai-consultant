# Техническое задание: Единый API-сервис проверки домашних заданий (AI Review + AI Detection)

## 1. Введение
Цель данного ТЗ – описать архитектуру и требования к реализации единого FastAPI-приложения, объединяющего функционал модулей `ai_detector` и `homework_reviewer`. 
Ключевые требования:
1. **Оптимизация пайплайна**: парсинг условия задачи и клонирование репозитория выполняются **строго один раз**.
2. **Централизация общих сущностей**: схемы данных (`models.py`) и промпты (`prompts.py`) вынесены в общий слой `src/common/`.
3. **Чистая архитектура**: API описан в `src/app.py`, а логика оркестрации вынесена в `src/core/pipeline.py`.

## 4. Требования к API (`src/app.py`)

### 4.1. Эндпоинт `POST /review`
- **Входные данные**: `repo_url` (str, Form) и `task_file` (UploadFile: PDF, DOCX, XLSX).
- **Выходные данные**: JSON, строго соответствующий модели `ReviewResponse` из `src.common.models`.

### 4.2. Управление жизненным циклом (`lifespan`)
При старте приложения инициализируется `Pipeline`, который получает экземпляры сервисов.
```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from src.core.pipeline import Pipeline
from src.common.clients import get_llm_client, get_openrouter_client
from src.ai_detector.service import AIDetectionService
from src.homework_reviewer.evaluator.grading_engine import GradingEngine

@asynccontextmanager
async def lifespan(app: FastAPI):
    detector_service = AIDetectionService(get_llm_client())
    reviewer_service = GradingEngine(get_openrouter_client())
    
    app.state.pipeline = Pipeline(
        detector=detector_service,
        reviewer=reviewer_service
    )
    yield
    app.state.pipeline = None

app = FastAPI(lifespan=lifespan)

# ... далее определение роута @app.post("/review") ...
```

### 5.1. Логика работы `Pipeline.run()`

1. **Парсинг условия (1 раз)**: `Pipeline` самостоятельно вызывает вынесенную функцию парсинга (из общего слоя `src/parsers/` или утилит) для извлечения критериев из `task_file`. Результат маппится в общую модель `TaskCriteria`. Внутренние парсеры `homework_reviewer` на этом этапе не вызываются.
2. **Клонирование (1 раз)**: `Pipeline` самостоятельно вызывает вынесенную функцию клонирования, которая скачивает `repo_url` во временную директорию. Функция просто возвращает путь к папке и **не содержит** логики автоудаления (никаких контекстных менеджеров).
3. **Параллельное выполнение**: `asyncio.gather()` запускает только методы итоговой оценки, которые на вход получают *уже готовые* локальный путь и текст ТЗ:
   - `detector.analyze_from_path(task_criteria, repo_path)`
   - `reviewer.evaluate_from_path(task_criteria, repo_path)`
   *(Эти методы внутри себя больше не содержат вызовов клонирования или парсинга ТЗ).*
4. **Очистка**: Гарантированное удаление временной директории (`shutil.rmtree`) в блоке `finally` **строго после** завершения обеих задач из `gather` (включая случаи падений с исключениями).
5. **Агрегация**: Сбор результатов от детектора и ревьюера в экземпляр общей схемы `ReviewResponse` и возврат.

## 6. Необходимые адаптации существующих модулей

1. **Единые схемы и конфигурация (`src/common/`)**: 
   - Все общие Pydantic-схемы и конфигурации держать в `src/common/models.py` и `src/common/settings.py`. 
   - Удалить дублирующиеся определения из локальных модулей и импортировать единые сущности из общего слоя.

2. **Единые клиенты и логика работы с LLM (`src/common/`)**: 
   - Создать `src/common/clients.py` для централизованной инициализации клиентов `AsyncOpenAI` (для локального LLM и OpenRouter) на основе `settings.py`. Это исключит дублирование конфигурации подключений и управление ключами.
   - Вынести общую логику взаимодействия с LLM (непосредственные вызовы API, обработка structured output, механизмы retries, парсинг и валидация ответов модели) в `src/common/llm.py`. Оба модуля (`ai_detector` и `homework_reviewer`) должны использовать этот единый слой-обёртку для обращения к моделям, избавившись от собственных дублирующих реализаций.

3. **Вынесение тяжелых I/O-операций**: 
   - Логику клонирования репозитория и парсинга файла с ТЗ необходимо вынести отдельно. 
   - Эти операции выполняются **строго один раз** в `src/core/pipeline.py` **до** запуска `asyncio.gather()` основных методов оценки.

4. **Адаптация методов детекции и ревью**: 
   - Методы, выполняющие непосредственно ревью (`homework_reviewer`) и детекцию ИИ (`ai_detector`), должны принимать на вход уже готовый `repo_path` (путь к локальному клону) и распарсенное ТЗ. 
   - Они не должны пытаться клонировать репозиторий или парсить файл с условием самостоятельно (внутренние вызовы `RepoCloner` и `TaskParser` из этих методов удаляются).

## R1. Единое место отчёта о сбое git-процесса (B1, B2 — DRY)

- **Decision**: два текущих дубля — хвост stderr (decode utf-8/replace →
  splitlines → последние 3 строки → заглушка «stderr git пуст») и обёртка
  OSError «Не удалось запустить git … проверьте, что git CLI установлен и
  доступен в PATH» — выносятся в два чистых модульных хелпера в
  **существующем** внутреннем модуле `src/ai_detector/_spawn.py`:
  `git_stderr_tail(stderr: bytes, limit: int = 3) -> str` и
  `git_spawn_failure_message(operation: str, exc: OSError) -> str`
  (сообщение — тот же русский шаблон с `{operation}` и `{exc}`).
  `RepoCloner` и `GitMetadataExtractor` вызывают эти хелперы; словесный
  состав сообщений остаётся дословным (Assumption: тексты ошибок — контракт).
- **Rationale**: `_spawn.py` — уже признанный низкий слой «git-плотнинга»
  пакета (FR-013-контекст: оба вызывающих оборачивают сбои запуска в
  доменную иерархию); DRY-единица получает естественного владельца без
  нового модуля и без изменения структуры пакета. Хелперы чистые функции —
  импортируемы и тестируемы напрямую (принципы I/III).
- **Alternatives considered**: (а) новый модуль `git_errors.py` — лишний файл
  для двух функций, без выигрыша в границах; (б) общий класс
  `GitProcessRunner`, обвязывающий spawn+ошибки+таймаут — чрезмерная
  абстракция: семантика вызовов различна (clone: таймаут 120 c + kill +
  token-маскирование; log/ls-files: простой run), общий раннер либо
  перегенерализуется, либо унаследует ветвления — выше риск регрессии при
  нулевой выгоды для контракта.

## R2. Владелец изменяемого состояния в `spawn_git` (B3 — ClassVar)

- **Decision**: в `_spawn.py` вводится приватный класс-владелец
  `_GitSpawnSupervisor` (не экспортируется) с ClassVar-состоянием:
  `SETTLE_TIMEOUT_SECONDS: ClassVar[float] = 2.0` (нынешний
  `SPAWN_SETTLE_TIMEOUT_SECONDS`) и
  `_REAPERS: ClassVar[set[asyncio.Task[None]]] = set()` (сильные ссылки на
  задачи-«сборщики», событие done-колбэка — `discard`). Вся логика
  `_settle_spawn_task`/`_reap_spawn_task` становится classmethod'ами класса;
  публичная функция `spawn_git(*argv)` сохраняет сигнатуру и становится
  тонкой обёрткой, делегирующей в classmethod класса (например
  `_GitSpawnSupervisor.spawn(*argv)`).
  Модульных глобалов в модуле не остаётся (кроме самого класса —
  неизменяемого объекта).
- **Rationale**: принцип V требует, чтобы общее состояние было ClassVar
  владельца; модульный экземпляр-реестр (альтернатива а) по-прежнему был бы
  модульным глобалом — нарушение. ClassVar + classmethod'ы позволяют
  сохранить модульный API `spawn_git` (tests monkeypatch именно его) без
  единого экземпляра в модуле. Поведение отмены-безопасности не меняется
  (покрытие B11 догоняет отдельно).
- **Alternatives considered**: (а) класс-реестр с модульным экземпляром
  `_registry = _ReaperRegistry()` — по-прежнему модульный глобал (мутация
  через методы не отменяет «глобал в модуле»); (б) передача реестра
  аргументом через `RepoCloner`/`GitMetadataExtractor` — ломает сигнатуру
  `spawn_git`, которую подменяют тесты, и тасует state между несвязанными
  классами (скрытая связность — ровно то, против чего принцип V);
  (в) отказ от реестра и крепление ссылок на самом spawn-задаче (атрибуты
  `asyncio.Task`) — недекларативный хаки-паттерн, ломается при сборке мусора.

## R3. Перенос констант на ClassVar владельцев (B4, B5 — ClassVar)

- **Decision**: перенос по владельцам:
  - `RepoCloner`: `CLONE_TIMEOUT_SECONDS`, `_GITHUB_HOSTS`,
    `_ACCESS_FAILURE_MARKERS` → `ClassVar` класса;
  - `LocalCodeAggregator`: `SUPPORTED_EXTENSIONS`, `EXCLUDED_DIRS`,
    `MAX_CONCURRENT_READS` → `ClassVar` (default-аргумент `__init__`
    читает `cls.MAX_CONCURRENT_READS`/класс по имени);
  - `GitMetadataExtractor`: `COMMIT_LOG_FORMAT`, `_FIELD_SEPARATOR` →
    `ClassVar`;
  - `LLMJudge`: `DEFAULT_LLM_MODEL` → `ClassVar`; `MAX_ATTEMPTS` —
    объявить явно как `ClassVar` (B5) — значение и использование в
    декораторе `@retry` не меняются;
  - `CommitInfo`: `COMMIT_HASH_PATTERN` → `ClassVar[str]` на модели
    (pydantic v2 не считает ClassVar полем; `Field(pattern=...)`
    ссылается на него через класс).
- **Rationale**: формулировка принципа V допускает на уровне модуля только
  неизменяемые класс-независимые константы без естественного владельца; все
  перечисленные имеют владельца (исключение в аудите не требуется).
  `COMMIT_HASH_PATTERN` — regex, но владелец есть (CommitInfo), поэтому
  переносится; после переноса модульных констант в `utils/models.py`
  не остаётся.
- **Alternatives considered**: оставить как module-константы и «оправдать»
  в аудите — против прямого текста принципа V («MUST … wherever possible»);
  перенос в `pydantic`-конфиг/Field-зависимости — без основания.

## R4. Типизированная граница `parsed` в LLM-судье (B8 — строгая типизация)

- **Decision**: вместо `return parsed  # type: ignore[return-value]` —
  модульная функция (или метод) с runtime-проверкой SDK-контракта:
  `if not isinstance(parsed, AIAssessmentResult): raise LLMJudgementError(
  «LLM-клиент вернул непредусмотренный тип структурированного ответа») from
  None`; `parsed is None` сохраняется отдельной веткой (`_TransientLLMError`,
  eligible для повтора — текущее поведение). `# type: ignore` удаляется;
  `Any` в коде пакета не остаётся.
- **Rationale**: SDK типизирует `message.parsed` как `Any` (объективно
  невозможно подписать иначе) — но наша граница делает утечку `Any`
  локальной в одну аннотированную точку и, более того, усиливает
  контракт: неожиданный тип теперь fail-loud вместо тихого прохода.
  Принципы I (no Any без необходимости) и II (не интерпретировать raw-текст)
  соблюдены: проверка типа объекта, а не текста.
- **Alternatives considered**: (а) `cast("AIAssessmentResult", parsed)` —
  гасит type-checker без runtime-гарантии, слабее; (б)
  `AIAssessmentResult.model_validate(parsed)` — пересоздаёт модель и
  маскирует отклонение SDK-контракта валидационной ошибкой другого класса;
  (в) оставить `type: ignore` с обоснованием — допустимо уставом только при
  «absolutely necessary», а граница R4 устраняет необходимость.

## R5. Ruff-шлюз на `src/` и `tests/` (B9, B10 — Development Workflow)

- **Decision**: из `[tool.ruff] exclude` удалить `"tests"` (`.venv`,
  `alembic` — не трогать); исправить все 14 нарушений базового аудита:
  - `src/` (5): RUF022 — отсортировать `__all__` в `__init__.py`; SIM105 ×2 —
    `contextlib.suppress(BaseException)` в `_spawn.py`; B905 — `zip(...,
    strict=True)` в `code_aggregator.py` (списки равной длины — инвариант
    `asyncio.gather`); UP041 в `repo_cloner.py` — **оставить**
    `(TimeoutError, asyncio.TimeoutError)` с целевым `noqa: UP041` и
    комментарием: на Python 3.10 (минимум `requires-python`)
    `asyncio.TimeoutError` — отдельный класс, замена на builtin сломает
    перехват; правило вычисляется от `target-version = "py311"`;
  - `tests/` (9): F401 — удалить неиспользуемый импорт; E501 ×2 — перенести
    строки/документ-стринги; UP012 ×3 — убрать явный `encoding`/`"utf-8"` у
    `str.encode()`; ASYNC110 ×2 — polling-циклы `while + await sleep(0.005)`
    заменить ожиданием `asyncio.Event`, который фейк выставляет при старте
    операции (детерминированнее и без спина); I001 — порядок импортов.
- **Rationale**: Устав фиксирует ruff как шлюз «MUST pass on src/ and
  tests/ before commit» — конфигурация, исключающая тесты, прямо
  противоречит Development Workflow. `noqa` на UP041 — единственный случай
  отклонения от правила, с явной технической причиной (сочетание
  `requires-python >=3.10` и `target-version py311`); правило Governance
  про явное обоснование отклонений соблюдено комментарием в коде и записью
  в аудите.
- **Alternatives considered**: (а) поднять `target-version` до `py310` —
  ruff станет честнее, но поменяет множество других срабатываний по пакету
  (масштаб вне фичи) и конфликтует с mypy `python_version = "3.11"` —
  отклонить; (б) прогнать `ruff --fix` целиком — 7 автофиксов, но SIM105/
  B905/ASYNC110/E501 требуют осознанных правок; автофиксы применяются
  точечно, в рамках среза, с проверкой поведения.

## R6. Паттерны устранения вложенных функций в тестах (B6 — No Nested Functions)

- **Decision**: каталог переноса (применяется ко всем 4 файлам):
  1. Локальные фейк-классы внутри тела теста (`FailingExtractor`,
     `EmptyHistoryExtractor`, `FailingCloneProcess`, `FakeGitProcess` и
     т.п.) → классы уровня модуля того же файла с явным конструктором
     (параметры вместо замыкания над локальными);
  2. Закрытие, «прокидывающее» фикс-объект в подменяемую функцию
     (`async def failing_spawn(*a, **k): return process`) → вызывающий
     объект уровня модуля: класс с `async def __call__` (например
     `_FixedProcessSpawner`) либо `functools.partial` на функцию уровня
     модуля — `partial` не является определением функции и под
     запрет не попадает;
  3. Оставшиеся замыкания (если будут) — только под исключение Устава
     (тривиальный одноразовый колбэк) и каждое — с записью в аудите.
- **Rationale**: формулировка принципа VI — «extract to module level with
  explicit arguments or make them methods of a class»; каталог реализует
  ровно эти два механизма + `partial` как не-функционный связующий
  объект. Имена модульных фейков — `_`-префикс (внутренние), что не
  затеняет публичный API.
- **Alternatives considered**: (а) общий `tests/fakes.py` для всех фейков —
  преждевременная генерализация: большинство фейков привязано к одному
  тест-файлу, меж-файловая общая точка появляется только у helpers (R7);
  (б) декоратор-«фабрика замыканий» (`def with_process(process): def wrap...`)
  — фабрика сама содержит вложенную функцию — против принципа.

## R7. Единый shared-модуль тестовых помощников (B7 — DRY в тестах)

- **Decision**: новый `tests/helpers.py` (уровень тестов, не импортируется
  из `src/`) с единственными определениями: `detector_temp_dirs() ->
  set[str]` (перечисление temp-каталогов детектора), `git_run(repo: Path,
  *args: str) -> None` (subprocess git для локальных репозиториев),
  `make_result(status: str = "green", **overrides: object) ->
  AIAssessmentResult` (общий конструктор вердикта, заменяющий два
  локальных `make_result` в `test_llm_judge.py`/`test_service.py` с
  объединением сигнатур). Все потребители (unit + integration) импортируют
  из него. Дубли в `demo/` **не трогаются** (Assumption: demo вне рамок) и
  фиксируются в аудите как known-out-of-scope.
- **Rationale**: B7 зафиксировал три дубля (temp-каталоги ×2, git ×2,
  make_result ×2 — последние с расходящимися дефолтами: объединение
  сигнатур — единственный случай, где поведение помощника расширяется,
  без изменения проверяемого поведения тестов).
- **Alternatives considered**: (а) `conftest.py`-фикстуры — помощники
  нужны и вне фикстур (прямые вызовы в ассертах), а conftest-импорты
  хелперов неконвенциональны; (б) `tests/common/`-пакет — избыточна для
  одного модуля.

## R8. Покрытие веток отмены `spawn_git` (B11 — Testing & Quality)

- **Decision**: в `tests/unit/test_spawn.py` (новый файл) — юнит-тесты
  веток, не покрытых в базе (40% модуля): двойная отмена вызывающего во
  время settle (ветка `except asyncio.CancelledError` в
  `_settle_spawn_task`, повторный `cancel()` осевшей задачи), сценарий
  «задача запуска не оседает» (fake spawn-задача, не завершающаяся до
  `SPAWN_SETTLE_TIMEOUT`), работа «сборщика» (`_reap_spawn_task`: kill
  процесса + wait, удаление из реестра ClassVar после done-колбэка),
  «сбой запуска проигрывает отмене» (spawn-задача с исключением →
  `None`). Механика: fake-процесс с учётчиками `kill()`/`wait()`,
  реальная `asyncio`-задача-мишень, вызов `spawn_git` в управляемой
  задаче с отменой в нужном окне. Цель: покрытие `_spawn.py` ≥ 90%
  (суммарное покрытие при этом растёт выше базовых 86%).
- **Rationale**: FR-008/SC-004: публичные методы покрыты включая
  задокументированные ветки; преамбула `_spawn.py` документирует
  CPython-бихевиор — каждая ветка есть задокументированное поведение,
  которое сегодня не защищено тестом.
- **Alternatives considered**: (а) довести до 100% модуля — включает
  неустранимые defensive-ветки (`except Exception: pass`), ради которых
  тесты-«на всё» снижают читаемость; порог 90% охватывает все
  поведенческие ветки; (б) только интеграционный регресс-тест shutdown —
  уже существует, но не покрывает reaper-ветки на юнит-уровне.

## R9. Артефакт аудита соответствия (FR-010)

- **Decision**: (а) скрипт `scripts/compliance_audit.py` — stdlib-only
  (`ast`, `pathlib`, `subprocess`, `json`), без новых зависимостей;
  (б) отчёт — markdown, пишется в `docs/compliance-audit.md` и коммитится;
  (в) запуск: `uv run python scripts/compliance_audit.py` (из корня
  репозитория); (г) механика проверок по принципам:
  - **V (ClassVar)**: AST-проход `src/`: модульные assignments — флаг
    «мутатные/с-собственником» (set/dict/list-литералы и вызовы,
    `frozenset`/`tuple`/`str`/`int` — кандидаты в допустимые остатки);
    остаточные — сверка с allowlist-таблицей в скрипте, где у каждой
    позиции есть строка-обоснование;
  - **VI (nested fns)**: AST-проход `src/` и `tests/`: FunctionDef/
    AsyncFunctionDef внутри FunctionDef/AsyncFunctionDef — флаг;
    allowlist-таблица одноразовых замыканий с обоснованием;
  - **IV (DRY)**: точечные проверки зафиксированных дублей: имена хелперов
    R1/R7 имеют ровно одно определение (поиск по AST + текст), отсутствие
    старых дублей (B1/B2/B7) — негативные проверки;
  - **I (типизация)**: grep-проверка `# type: ignore` в `src/` (0) и
    `: Any`/`-> Any` (0 без обосновывающего комментария в строке);
  - **II (LLM)**: статическая проверка, что `LLMJudge` использует
    `beta.chat.completions.parse` с `response_format=` и `temperature=0`
    (защита от регрессии контракта);
  - **III/Workflow**: запуск `ruff check src tests` (ожидание: 0) и
    `pytest` (ожидание: green, coverage ≥ базовой) с записью результатов
    в отчёт.
  Формат отчёта — по контракту [contracts/audit-report.md](./contracts/
  audit-report.md).
- **Rationale**: FR-010 требует воспроизводимости («перепускается
  командой») и полноты (все принципы + Workflow); stdlib-only — минимум
  (Assumption: без новых зависимостей); markdown-отчёт в `docs/` — видимый
  артефакт для ревью (Governance: обоснование отклонений — письменное).
- **Alternatives considered**: (а) markdown-отчёт без скрипта —
  невоспроизводим; (б) отдельный dev-пакет с linter-плагинами — новые
  зависимости, расширение набора инструментов (запрещено Assumption);
  (в) аудит как pytest-тесты — смешение ответственностей: тесты
  проверяют поведение, аудит — свойства кодовой базы; кроме того,
  аудит-тесты пришлось бы прогонять до implement-срезов.

## R10. Порядок инкрементальных срезов (FR-009)

- **Decision**: порядок срезов (каждый — зелёный pytest + зелёный ruff по
  обоим каталогам; зависимость → стрелка):
  1. **S1 — шлюз**: `pyproject.toml` (exclude: убрать `tests`) + все
     механические ruff-фиксы (R5). После S1 шлюз реально работает;
  2. **S2 — ClassVar-переносы** (R2, R3) + адаптация импортов в тестах;
  3. **S3 — DRY git-ошибкоотчёта** (R1) + адаптация тестов к новым
     внутренним местам;
  4. **S4 — типизированная граница `parsed`** (R4);
  5. **S5 — рефакторинг тестов** (R6, R7): модульные фейки, helpers.py,
     Event-окладки ASYNC110;
  6. **S6 — новые юнит-тесты `spawn_git`** (R8, новый файл
     `tests/unit/test_spawn.py`);
  7. **S7 — аудит** (R9): скрипт + отчёт + финальный прогон всех шлюзов.
  S2–S4 параллельны друг другу (независимые файлы), но в tasks.md
  упорядочиваются последовательно для детерминированного implement;
  S5 не зависит от S3/S4, но требует S1 (иначе шлюз по тестам не зелёный);
  S7 — последним (аудирует финальное состояние).
- **Rationale**: FR-009 запрещает срезы с красным шлюзом; S1 первым,

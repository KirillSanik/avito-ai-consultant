# Contract: Артефакт аудита соответствия (compliance audit report)

**Feature**: 002-constitution-refactor | **Status**: normative
**Генератор**: `scripts/compliance_audit.py` | **Цель**: `docs/compliance-audit.md`

Контракт формата и поведения артефакта, требующегося FR-010 (воспроизводимый
аудит соответствия Уставу) и Governance (явное обоснование каждого отклонения).

## 1. Команда

```bash
uv run python scripts/compliance_audit.py
```

- Запуск — из корня репозитория; аргументы не требуются.
- Зависимости: только stdlib Python (`ast`, `pathlib`, `subprocess`, `json`,
  `datetime`) — без новых packages (Assumption фичи).
- Выходные коды: `0` — все принципы `PASS` (допущены обоснованные
  `DEVIACTION`); `1` — найдено необоснованное отклонение либо шлюз (ruff/
  pytest) не пройден; `2` — сбой самого аудита (некорректный запуск, нет
  интерпретатора).

## 2. Формат отчёта (markdown, `docs/compliance-audit.md`)

Обязательная структура (порядок разделов фиксирован):

1. **Шапка**: `# Compliance Audit — ai_detector`; строки: дата/время
   генерации (ISO 8601, локальное), версия Устава (`1.1.0`), git HEAD
   (короткий хеш), результат-резюме (одна строка: PASS / N отклонений).
2. **Раздел на каждый проверяемый блок** (фиксированный перечень):
   `I. Architectural Rules`, `II. LLM Interaction Rules`, `III. Testing &
   Quality`, `IV. DRY`, `V. ClassVar Over Module Globals`, `VI. No Nested
   Functions`, `Technology Stack`, `Development Workflow`.
   Каждый раздел: строка статуса `PASS` или `DEVIACTION (N)`; затем таблица
   доказательств:

   | Проверка | Местоположение | Наблюдение | Статус |
   |---|---|---|---|
   | <имя механической проверки> | `src/ai_detector/…` | <что увидел аудит> | ok / deviation |

3. **Обоснования**: отдельный подраздел `## Обоснованные отклонения` —
   таблица `Отклонение | Местоположение | Обоснование` (обоснование —
   дословно из allowlist-таблицы генератора; свободные тексты в отчёт не
   попадают).
4. **Итог**: счётчики — проверок всего, `ok`, `deviation`, обоснованных /
   необоснованных отклонений; строка «Вывод».

## 3. Правила статусов

- `PASS` — ни одной строки `deviation` в разделе.
- `DEVIACTION (N)` — N строк `deviation`; каждая **обязана** иметь запись в
  «Обоснованных отклонениях». Строка `deviation` без обоснования →
  аудит завершается с кодом `1` (требование Governance).
- Раздел `Technology Stack`: проверка отсутствия новых runtime-зависимостей
  относительно `pyproject.toml` на момент базового снимка.
- Раздел `Development Workflow`: фиксирует результат запуска шлюзов
  (`ruff check src tests` → 0; `pytest` → green, покрытие ≥ 86%) — их
  вывод включается в раздел как доказательство (кратко: итоговые строки).

## 4. Механика проверок (обязательный минимальный набор)

| Блок | Механика |
|---|---|
| I | Поиск `# type: ignore` и явных `Any` в `src/` — 0 без обоснования |
| II | Статическая проверка `LLMJudge`: `beta.chat.completions.parse`, `response_format=`, `temperature=0`; отсутствие raw-text-парсинга ответа (нет `re.`-поиска по тексту LLM-ответа) |
| III | Покрытие из запуска pytest: публичные методы — строки доказательств; `_spawn.py` ≥ 90% |
| IV | Отрицательные проверки дублей B1/B2/B7: старые имена определений — 0 вхождений; имена shared-хелперов (R1/R7) — ровно 1 определение |
| V | AST: модульные assignments в `src/` — классификация мутатные/immutable; immutable — сверка с allowlist-таблицей (у каждой позиции строка-обоснование) |
| VI | AST `src/` + `tests/`: FunctionDef/AsyncFunctionDef внутри функции; сверка с allowlist одноразовых замыканий (обоснование у каждой позиции) |
| Workflow | Запуск ruff (0) и pytest (green, ≥ 86%) |

Allowlist-таблицы хранятся в самом генераторе (data-структуры в
`compliance_audit.py`) — они и есть «письменное обоснование» по Governance.

## 5. Поведение

- **Полная перегенерация**: файл перезаписывается целиком; append не
  допускается (история отчётов — в git).
- **Идемпотентность**: повторный запуск при неизменном коде — идентичный
  отчёт (кроме полей шапки, зависящих от HEAD).
- Аудит **не изменяет** код и конфигурацию — только читает, запускает
  шлюзы в режиме отчёта и пишет отчёт.

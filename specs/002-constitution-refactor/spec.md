# Feature Specification: Конституционный рефакторинг кодовой базы (Constitution Refactor)

**Feature Branch**: `002-constitution-refactor`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "Провести рефакторинг проекта с учётом constitution.md"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Ядро пакета соответствует Уставу без изменения поведения (Priority: P1)

Мейнтейнер проекта рефакторит исходный код пакета детектора (слои сбора данных,
оценки и оркестрации) так, чтобы каждое из шести принципов Устава
(`.specify/memory/constitution.md`, v1.1.0) выполнялось в коде пакета, — при этом
наблюдаемое поведение публичного API остаётся идентичным: потребители
(примеры в README, demo-скрипты) работают без единой правки.

**Why this priority**: Это суть фичи. Пока в коде пакета есть нарушения принципов
(дублирование логики, модульные глобалы вместо ClassVar, нестрогая типизация),
Устав не является рабочим инструментом: ревью и дальнейшие изменения платят за
разрастание расхождений. Этот сценарий — минимально ценный срез: «пакет чист,
поведение то же».

**Independent Test**: Тестируется независимо: запускается полный набор
автоматических тестов до и после изменения — они зелёные, публичный экспорт
пакета, иерархия исключений и схема вердикта не изменились; аудит-отчёт
(Story 4) подтверждает выполнение принципов для исходного кода пакета.

**Acceptance Scenarios**:

1. **Given** исходный код пакета с задокументированными в базовом аудите
   отклонениями (дублирование git-ошибкоотчёта, модульные глобалы с естественным
   владельцем-классом, обход строгой типизации), **When** рефакторинг завершён,
   **Then** каждое отклонение устранено: у каждой единицы логики — единственное
   авторитетное представление, общее состояние — класс-атрибуты владеющих классов,
   а неподписанных обходов типов нет.
2. **Given** любой потребитель публичного API (пример из README, demo-скрипт),
   **When** он запускается против отрефакторенного пакета, **Then** ему не
   требуется ни одной правки: экспорт, сигнатуры, схема вердикта, семантика
   повторов LLM-запросов, гарантированное удаление временной копии и тексты
   ошибок по контракту — без изменений.
3. **Given** полный набор автоматических тестов (базовые 67), **When** они
   запускаются после рефакторинга ядра, **Then** все проходят без изменения
   проверяемого поведения (тесты могут быть переработаны в рамках Story 3, но
   множество проверяемого поведения не сокращается).

### User Story 2 - Шлюзы качества работают как объявлено в Уставе (Priority: P2)

Разработчик готовит коммит: статический анализ (ruff) теперь реально проходит
**и** для исходного кода, **и** для тестов — каталог тестов не исключён из
анализа — а покрываемость не падает ниже базового уровня, а шлюз покрываемости
(30%) продолжает выполняться.

**Why this priority**: Устав (Development Workflow) требует, чтобы анализ
проходил по `src/` и `tests/` до коммита. Сейчас конфигурация анализа исключает
тесты, а по исходному коду уже есть 5 нарушений — объявленный шлюз фактически
не работает, и новые отклонения будут накапливаться. Без этого сценария
результат Story 1 деградирует обратно.

**Independent Test**: Тестируется независимо: запуск статического анализа по
обоим каталогам даёт ноль нарушений; запуск тестов со сборкой покрываемости
даёт зелёный прогон и покрытие не ниже базового (86%); конфигурация анализа
больше не исключает каталог тестов.

**Acceptance Scenarios**:

1. **Given** конфигурация статического анализа, исключающая каталог тестов,
   **When** рефакторинг завершён, **Then** каталог тестов включён в анализ и
   анализ завершается с нулём нарушений по обоим каталогам (база: 5 нарушений в
   `src/` + 9 в `tests/`).
2. **Given** базовая покрываемость 86% (шлюз 30%), **When** рефакторинг
   завершён, **Then** общая покрываемость не ниже базовой и шлюз 30% пройден.
3. **Given** любой промежуточный срез рефакторинга, **When** он фиксируется,
   **Then** на нём зелёны и тесты, и статический анализ (рефакторинг
   инкрементальный, «big bang» не допускается).

### User Story 3 - Код тестов подчинён тем же принципам (Priority: P2)

Мейнтейнер правит тесты: общие вспомогательные функции существуют в единственном
представлении, вложенных функций в телах тестов нет (кроме тривиальных
одноразовых замыканий-колбэков, допущенных Уставом), и тесты проходят статический
анализ.

**Why this priority**: Тесты — часть кодовой базы и сейчас несут свои
отклонения: дублирующиеся помощники (перечисление temp-каталогов детектора,
запуск git для локального репозитория) и функции, объявленные внутри функций.
Устав не даёт тестам исключений; непроверяемый рост «тестового» кода
задаёт темп деградации всего модуля.

**Independent Test**: Тестируется независимо: каждый дублирующийся помощник
имеет одно определение; в тестах нет вложенных функций за пределами
допущенного исключения; статический анализ по каталогу тестов — ноль
нарушений; все поведенческие проверки сохранены.

**Acceptance Scenarios**:

1. **Given** две и более файловые копии одного и того же тестового помощника
   (перечисление temp-каталогов, фикстура локального git-репозитория),
   **When** рефакторинг завершён, **Then** помощник определён единожды и
   используется всеми потребителями.
2. **Given** функция, объявленная внутри тела функции/теста (не тривиальное
   одноразовое замыкание), **When** рефакторинг завершён, **Then** она
   вынесена на уровень модуля или стала методом класса; оставшиеся замыкания
   соответствуют исключению Устава и задокументированы в аудите.

### User Story 4 - Аудит соответствия воспроизводим и зафиксирован (Priority: P3)

Ревьюер, не доверяя устным заявлениям, запускает воспроизводимую проверку
соответствия Уставу и получает отчёт: по каждому из шести принципов и по
Development Workflow — статус (выполнено / отклонение) с указанием мест и,
для каждого задокументированного отклонения, явным обоснованием.

**Why this priority**: Устав (Governance) требует, чтобы каждое отклонение
имело явное документированное обоснование. Без отчёта «соответствие» —
неверифицируемое утверждение; с отчётом — воспроизводимое свойство, которое
можно перепроверять при каждом последующем изменении.

**Independent Test**: Тестируется независимо: отчёт существует в репозитории,
его можно воспроизвести командой (собирает/проверяет то, что проверяет), и он
отражает фактическое состояние кода — включая единичные допустимые отклонения
с обоснованием.

**Acceptance Scenarios**:

1. **Given** завершённый рефакторинг, **When** запущен аудит соответствия,
   **Then** по каждому принципу Устава (I–VI) и Development Workflow отчёт
   показывает статус; любое «отклонение» сопровождается явным обоснованием, а
   не умолчанием.
2. **Given** единичное допустимое отклонение (например, минимальное
   типизационное наложение, вынужденное внешним SDK), **When** открыт
   аудит-отчёт, **Then** оно перечислено с обоснованием в соответствии с
   правилом Устава «Any — только когда абсолютно необходимо» и с процедурой
   Governance.

### Edge Cases

- **Конфликт принципа с сохранением поведения** (например, перенос константы
  меняет её внутреннее место, на которое ссылаются тесты): публичный
  контракт неизменен; внутренние имена/места могут меняться; тесты
  адаптируются к новым внутренним местам без изменения проверяемого
  поведения.
- **Константа без естественного владельца** (строка протокола/формата, regex):
  остаётся на уровне модуля по формулировке принципа V; факт и обоснование
  фиксируются в аудите.
- **Замыкание, явно не «тривиальное одноразовое»**: принимается решение по
  формулировке исключения Устава; при сомнении функция выносится на уровень
  модуля; каждое оставленное замыкание задокументировано в аудите.
- **Внешний SDK отдаёт структурированный ответ в нетипизированном поле**:
  вводится минимальная типизированная граница без изменения контракта
  Structured Output; regex-парсинг raw-текста ответа запрещён (принцип II).
- **Срез рефакторинга красит шлюз** (тест или статический анализ): срез не
  фиксируется; работа возвращается к последнему зелёному состоянию и
  дробится на меньшие инкременты.
- **Обнаруженное в ходе рефакторинга расхождение поведения с задокументированным
  контрактом**: поведение приводится к контракту, факт и решение
  документируются в аудите; «улучшать» поведение, не зафиксированное
  контрактом, молча не допускается.
- **Временное снижение покрываемости** (логика перенесена, тесты ещё не
  дотянуты): не допускается между срезами — покрывающие тесты добавляются
  в том же срезе, что и перенос.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Рефакторинг MUST сохранять наблюдаемое поведение публичного
  контракта: состав экспорта пакета, иерархию доменных исключений, схему
  вердикта (пять полей), семантику повторов LLM-запросов (3 попытки,
  экспоненциальный бэкофф для временных сбоев, немедленная ошибка для
  неисправимых), гарантированное удаление временной копии репозитория при
  любом исходе, а также содержательные тексты ошибок по контракту
  (русский язык, без токена доступа и без пути к временному каталогу).
  Правка потребителям (README, demo) не требуется.
- **FR-002**: В исходном коде пакета MUST быть устранено дублирование логики:
  каждая единица знания/логики — в единственном авторитетном представлении.
  Конкретно (по базовому аудиту): отчёт о сбое git-процесса (хвост stderr с
  пустым-заглушкой и обёртка «git CLI недоступен» с подсказкой) сейчас
  существует в двух независимых реализациях (клонирование и извлечение
  метаданных) — после рефакторинга она существует единожды.
- **FR-003**: MUST быть устранены изменяемые модульные глобальные состояния:
  общее состояние/конфигурация — класс-атрибуты (`typing.ClassVar`)
  владеющего класса. На уровне модуля остаются допустимы только
  неизменяемые, класс-независимые константы (regex, строки протокола/формата)
  без естественного владельца; каждая такая остаточная константа
  задокументирована в аудите.
- **FR-004**: MUST быть устранены функции, объявленные внутри других функций,
  в исходном коде пакета; допущено только исключение Устава — тривиальное
  одноразовое замыкание-колбэк, где вынос добавил бы именное шум без
  переиспользования. Оставшиеся исключения задокументированы в аудите.
- **FR-005**: Типизация MUST оставаться строгой (PEP 484) без неподписанных
  обходов: текущий `# type: ignore`, скрывающий нетипизированное поле
  внешнего SDK, заменяется явной типизированной границей с обоснованием;
  каждое оставшееся обращение к `Any` (если останется) имеет явный
  обосновывающий комментарий по правилу Устава «No Any unless absolutely
  necessary».
- **FR-006**: Статический анализ (ruff, набор правил закреплён в `pyproject.toml`)
  MUST проходить с нулём нарушений по **обоим** каталогам — исходного кода и
  тестов; конфигурация MUST не исключать каталог тестов из анализа.
- **FR-007**: Код тестов MUST быть приведён к тем же принципам, что и пакет:
  дублирующиеся помощники — в единственном представлении (по базовому аудиту:
  перечисление temp-каталогов детектора и запуск git для локального
  репозитория), вложенные функции — только допущённые исключения (FR-004),
  статический анализ по каталогу тестов — ноль нарушений. Множество
  поведенческих проверок не сокращается.
- **FR-008**: Покрываемость MUST не снижаться: каждый публичный метод
  покрывается тестами, включая его задокументированные поведенческие ветки
  (в частности, пути отмены запуска git-процесса, слабо покрытые в базе), а
  общая покрываемость не ниже базового уровня; шлюз покрываемости 30%
  сохраняется.
- **FR-009**: Рефакторинг MUST быть инкрементальным: каждый фиксируемый срез
  оставляет зелёным полный набор тестов и прохождение статического анализа;
  «большой взрыв» (срез, в котором хотя бы один шлюз краснеет) не
  допускается.
- **FR-010**: MUST быть создан воспроизводимый артефакт аудита
  соответствия: проверка, сопоставляющая каждый принцип Устава (I–VI) и
  Development Workflow со статусом «выполнено/отклонение» и, для отклонения,
  явным обоснованием; артефакт хранится в репозитории и его можно
  перепустить командой.

### Key Entities

- **Публичный контракт API**: неизменяемый артефакт рефакторинга — состав
  экспорта пакета, иерархия доменных исключений, схема вердикта, семантика
  ошибок и повторов, гарантия удаления временной копии. Ограничения:
  определён контрактами фичи 001; любое изменение — за пределами фичи и
  требует отдельного обоснования по Governance.
- **Артефакт аудита соответствия**: отчёт «принцип → статус → места →
  обоснование» для принципов I–VI и Development Workflow; атрибуты:
  воспроизводимость (перепускается командой), полнота (все принципы),
  обоснованность отклонений.
- **Базовый аудит (snapshot отклонений)**: начальное состояние кодовой базы,
  зафиксированное на 2026-09-04 (таблица ниже); атрибуты: конкретные места
  отклонений, измеримые метрики (тесты, покрытие, нарушения анализа).
  Используется как критерий «до/после».

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% набора автоматических тестов проходит после рефакторинга;
  размер набора не меньше базового (база: 67 тестов, 0 провалов).
- **SC-002**: 0 нарушений статического анализа (закреплённый набор правил) в
  каталоге исходного кода и 0 — в каталоге тестов (база: 5 + 9).
- **SC-003**: Аудит соответствия показывает «выполнено» по всем шести
  принципам Устава; число необоснованных отклонений — 0 (каждое оставшееся
  отклонение имеет явное письменное обоснование).
- **SC-004**: Общая покрываемость не ниже базовой (≥ 86%) при сохранении
  шлюза 30%; публичные методы покрыты, включая задокументированные ветки
  отмены (база: ветки отмены запуска git-процесса покрыты частично).
- **SC-005**: Потребителям публичного API не требуется ни одной правки кода:
  примеры README и demo-скрипты работают без изменений (критерий
  «0 правок потребителя»).
- **SC-006**: 100% зафиксированных срезов рефакторинга инкрементальны:
  каждый срез имеет зелёные тесты и прохождение статического анализа
  (верифицируется по истории фиксаций/журналу поставки).

## Assumptions

- **Устав — единственный источник истины**: `.specify/memory/constitution.md`
  v1.1.0; где это спецификация и Устав расходятся — приоритет у Устава
  (раздел Governance).
- **Публичный контракт заморожен**: контракт описан в фиче
  `001-homework-ai-detector` (contracts/public-api.md и связанные документы);
  рефакторинг не меняет ни публичный экспорт, ни наблюдаемое поведение.
- **Тексты ошибок — часть контракта**: формулировки сообщений (русский язык,
  маскирование токена и temp-пути, подсказки о токене) сохраняются
  дословно; улучшать формулировки — отдельная фича.
- **Набор инструментов-шлюзов не расширяется**: шлюзы — те, что объявлены в
  Уставе (статический анализ + тесты с покрываемостью). Введение новых
  шлюзов (например, отдельного инструмента проверки типов) — вне рамки
  фичи; текущая разрешительная конфигурация mypy не меняется и не
  считается отклонением (он не является объявленным шлюзом).
- **Тесты — в рамке принципов**: код тестов подчиняется тем же принципам
  Устава, что и пакет; demo/ и docs/ рефакторингу не подлежат, но должны
  остаться валидными (FR-001/SC-005).
- **Живой LLM недоступен**: тесты полагаются на заглушки (существующий
  паттерн); интеграционные проверки используют локальные git-репозитории
  (существующий паттерн). Рефакторинг не требует запущенного LLM-сервера.
- **Базовые метрики (2026-09-04)**: 67 тестов зелёные; общая покрываемость
  86% (шлюз 30%); 5 нарушений анализа в исходном коде + 9 в тестах, при этом
  каталог тестов исключён из конфигурации анализа.
- **Исключения Устава применяются буквально**: «тривиальное одноразовое
  замыкание» и «неизменяемая класс-независимая константа» трактуются по
  формулировкам Устава; каждое применение фиксируется в аудите.

задокументируется (FR-002…FR-005, FR-010).

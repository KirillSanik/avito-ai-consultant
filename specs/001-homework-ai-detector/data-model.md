# Data Model: Homework AI Detector

**Feature**: 001-homework-ai-detector | **Date**: 2026-09-03
Связь со spec: раздел *Key Entities*; с research: §2–§11.

## Entities

### 1. `CommitInfo` (запись коммита)

| Поле | Тип | Правила валидации | Источник |
|------|-----|-------------------|----------|
| `hash` | `str` | 40 hex-символов: `^[0-9a-f]{40}$` | `%H` из `git log` |
| `author` | `str` | непустая строка | `%an` |
| `date` | `str` | ISO 8601 с таймзоной (`%aI`), парсится `datetime.fromisoformat` | `%aI` |
| `message` | `str` | однострочный subject (`%s`); при не-JSON строке — `MetadataExtractionError` (fail-loud) | `%s` |

- **Отношения**: множество `CommitInfo` образует *историю коммитов* репозитория (упорядочено по убыванию даты, как отдаёт `git log`).
- **Правило**: merge-коммиты отсутствуют в сущности — исключены на уровне команды (`--no-merges`, FR-003).
- **Пример**: `{"hash": "a1b2…", "author": "student", "date": "2026-03-01T14:22:05+03:00", "message": "initial commit"}`

### 2. `SourceFile` (файл исходного кода)

| Поле | Тип | Правила |
|------|-----|---------|
| `path` | `str` | относительный posix-путь от корня репозитория |
| `content` | `str` | **полное** содержимое, UTF-8; усечение запрещено (FR-004) |

- **Отношения**: принадлежит *дереву файлов*; попадает в агрегированный код только если расширение ∈ whitelist (`.py`, `.go`, `.rs`, `.js`, `.ts`, `.java`, `.cpp`, `.md`) и путь не пересекает blacklist-директории (`.git`, `__pycache__`, `venv`, `node_modules`, `.idea`, `.vscode`).
- **Правило**: бинарный/не-UTF8 файл пропускается с предупреждением в лог (whitelist текстовых расширений делает это редким).

### 3. `RepoMetadata` (метаданные репозитория)

| Поле | Тип | Значение |
|------|-----|----------|
| `commits` | `list[CommitInfo]` | полная история не-merge коммитов (может быть пустой — edge case) |
| `file_tree` | `list[str]` | полный список файлов HEAD (`git ls-files`), включая не-кодовые — «Структура файлов» в промпте |
| `full_code` | `str` | агрегированный код с маркерами (см. §4) |

- **Отношения**: агрегат двух независимых источников (`GitMetadataExtractor` + `LocalCodeAggregator`), собираемых **параллельно** (`asyncio.gather`, FR-006); существует только внутри вызова `analyze` — не персистируется (модуль без состояния).

### 4. `AIAssessmentResult` (оценка — итоговая сущность)

| Поле | Тип | Правила валидации |
|------|-----|-------------------|
| `status` | `Literal["green", "yellow", "red"]` | обязательное; семантика — FR-015 |
| `confidence` | `float` | `0.0 ≤ confidence ≤ 1.0` (pydantic `ge=0.0, le=1.0`) |
| `reasoning` | `str` | непустое; развернутое обоснование **на русском языке** (FR-008) |
| `ai_indicators` | `list[str]` | список конкретных признаков AI-генерации (пустой список допустим, объясняется в `reasoning`) |
| `human_indicators` | `list[str]` | список признаков человеческой работы (то же правило) |

- **Отношения**: является финальным продуктом пайплайна; возвращается `AIDetectionService.analyze` наружу.
- **Запрет**: поле `task_compliance_score` (или эквивалент) **не существует** в схеме (FR-009) — при его получении от LLM схема его отбросит (pydantic extra=ignore), но промпт не предлагает его.
- **Семантика статусов** (критерии из FR-015, закреплены в system prompt):
  - `green` — постепенная история, осмысленные сообщения, неидеальности, специфичные имена, код решает именно поставленную задачу, комментарии по делу.
  - `yellow` — качественный код, но подозрительная история (1–2 коммита через минуту), «водянистые» ИИ-комментарии при признаках ручной адаптации.
  - `red` — один «initial commit», бездушная идеальная структура, галлюцинации в комментариях, код мимо критериев, артефакты нейросетей («Конечно, вот ваш код», «Sure, here is the solution»).

### 5. `AIDetectionError` (иерархия ошибок)

```text
AIDetectionError
├── RepoCloneError          # неудачное/таймаутное клонирование, отсутствие прав (приватный без токена)
├── MetadataExtractionError # сбой git log/ls-files, невалидная строка JSON
├── CodeAggregationError    # сбой чтения файлов; «no supported source files» (edge case)
└── LLMJudgementError       # LLM недоступна после 3 повторов, context overflow, parsed is None
```

Правило: наружу пробрасывается только эта иерархия; частичные/«мусорные» результаты не возвращаются (FR-013). Токен никогда не попадает в сообщение ошибки (research §3).

## Lifecycle (состояния пайплайна)

```text
IDLE → CLONING → COLLECTING (metadata ∥ code, параллельно) → EVALUATING (≤3 повторов) → COMPLETED
                ↘ FAILED (любая стадия) → [гарантированная очистка temp] → COMPLETED/FAILED
```

- Клон существует **только** в интервале `CLONING → EVALUATING` внутри `async with cloner.clone(...)`; очистка — в `finally` на любом выходе (FR-010, SC-004).
- `EVALUATING` → при временном сбое: RETRY (до 3, экспоненциальный бэкофф) → EVALUATING; при устойчивом/overflow — FAILED (research §9–§10).

## Prompt Payload (вход в LLM, структура)

```text
system:  роль старшего инженера-ревьюера; критерии вердикта green/yellow/red (дословно ТЗ §5);
         «ответ строго в JSON по схеме, без текста вне JSON»
user:    1. КРИТЕРИИ ЗАДАНИЯ:      {task_criteria}
         2. МЕТАДАННЫЕ РЕПОЗИТОРИЯ:
            - Структура файлов:    {file_tree}        # list[str] из RepoMetadata
            - История коммитов:    {commit_history}   # форматированные CommitInfo
         3. ПОЛНЫЙ ИСХОДНЫЙ КОД:   {full_code}        # с маркерами --- FILE: … ---
```

Детали форматов и строгая JSON-схема — в [contracts/llm-structured-output.md](./contracts/llm-structured-output.md).
